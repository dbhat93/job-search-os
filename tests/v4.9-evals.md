# v4.9 Eval Test Suite

**Version**: 4.9 - regression coverage for the commands added or heavily changed since v3.2
**Test count**: 24 (4 apply + 3 sync + 3 negotiate + 2 salary + 1 concerns + 1 debrief-alias + 2 hype + 2 kickoff + 1 pitch + 1 practice + 1 reflect + 1 thankyou + 1 help + 1 integration)
**Fixtures**: `tests/fixtures/`
**Scope**: The v3.2 suite covered research/linkedin/outreach/prep/present + a small regression set. It never covered `apply`, `negotiate`, `sync`, `salary`, `concerns`, `debrief`, `hype`, `kickoff`, `pitch`, `practice`, `reflect`, `thankyou`, or `help`. Those are the highest-churn commands as of v4.9 (apply went to v4.9, sync gained DERIVED-block regen and the drift sweeps, comp scoring moved upstream). This suite closes that gap.

## How to Run

Run one Feature group per fresh session to avoid state bleed. Copy the named fixture (or build the described setup) to `coaching_state.md` before each test. Fixtures marked `[create]` do not exist yet and must be authored before the test can run; a minimal fixture is a coaching state containing only the sections the test names.

**Writing-command note**: `apply`, `negotiate`, `pitch`, `thankyou` all route through the Writing Quality Gate in `references/cross-cutting.md`. Every test on those commands must assert the two hard rules: no em dashes and no AI-isms (see `~/.claude/CLAUDE.md` writing rules and the voice file). A draft that violates either fails the test regardless of content quality.

## Feature 1: `apply`

**Reference**: `references/commands/apply.md` (Answer Structure, Step 0c Duplicate Check, evidence-integrity rule) + `references/cross-cutting.md` (Writing Quality Gate)
**Fixture**: `tests/fixtures/mock-coaching-state-storybank.md` - a state with Profile, 3 storybank entries with quantified impact, a Proof Bank, and one Interview Loop.

### Test 1.1: Happy Path - Two Questions With Storybank Support

**Setup**: Use the storybank fixture. Storybank contains a fraud/AI-agents story with metrics.
**Trigger**: `apply [Acme] "Why are you interested?" "Tell us about an AI product you built."`
**Expected**: Two answers. Each follows the v4.9 structure (one company-specific hook, evidence-backed proofs from the storybank, honest gap-bridge only if a material gap exists). ~100-200 words each.
**Pass criteria**:
- [ ] Both answers use real storybank evidence, not invented facts
- [ ] No em dashes anywhere
- [ ] No AI-isms (no "X instead of Y" antithesis, no rule-of-three flourish, no mic-drop kicker)
- [ ] Company-specific hook present in each

### Test 1.2: Word / Character Limit Respected

**Setup**: Same fixture.
**Trigger**: `apply [Acme] "Why us? (max 60 words)"`
**Expected**: Answer is 60 words or fewer.
**Pass criteria**:
- [ ] Word count <= 60
- [ ] Substance preserved despite the limit

### Test 1.3: Evidence Integrity - No Supporting Story

**Setup**: Same fixture, but the storybank has no story about people-management.
**Trigger**: `apply [Acme] "Describe a time you managed a large team."`
**Expected**: Does NOT fabricate a team-management story or invent headcount/metrics. Either surfaces the honest gap and offers a bridge from adjacent real experience, or asks the candidate for the raw material.
**Pass criteria**:
- [ ] No invented metrics, headcount, titles, or events
- [ ] Gap handled honestly (bridge from real experience OR explicit ask)

### Test 1.4: Duplicate / Re-application Check (Step 0c)

**Setup**: Storybank fixture plus an Outcome Log entry: `Acme - rejected - 2026-06-01`.
**Trigger**: `apply [Acme] "Why do you want to work here?"`
**Expected**: Flags the prior rejection before drafting and asks whether to proceed, rather than silently drafting a fresh application to a company that already passed.
**Pass criteria**:
- [ ] Prior-rejection flag surfaced before any draft
- [ ] Waits for candidate confirmation
